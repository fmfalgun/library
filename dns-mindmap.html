DNS mindmap

Eight branches to remember how DNS works, who plays which role, and how to test any server’s claims.

DNS
1. Roles in a lookup Memory line: you ask the resolver, it asks root, then TLD, then authoritative.
Recursive resolverDoes the hunting for you and caches. ISP, 8.8.8.8, 1.1.1.1
Root serverTop of the tree. Points to the TLD server.
TLD serverHandles .com, .org, .in. Points to the domain’s server.
Authoritative serverHolds the real records. Gives the final answer.
2. Server configurations Who owns the data, and who just passes it on.
Primary (master)Original, editable zone data.
Secondary (slave)Read-only synced copy for backup and load.
Caching-onlyRemembers answers, hosts no zones.
ForwarderHands queries to another DNS server.
3. Query types Recursive = “get me the answer”. Iterative = “tell me who to ask next”.
RecursiveServer must return a final answer or an error.
IterativeServer returns a referral, client keeps asking.
Non-recursiveAnswered from cache or the server’s own zone.
4. Record types Names to addresses (A, AAAA), aliases (CNAME), mail (MX), and housekeeping.
AName to IPv4
AAAAName to IPv6
CNAMEAlias to another name
MXMail servers
NSAuthoritative name servers
TXTFree text: SPF, DKIM, verification
PTRIP to name (reverse lookup)
SOAZone admin info
SRVWhere a specific service lives
5. Other classifications Who can use it, and how well is it protected.
PublicInternet-facing names and open resolvers.
PrivateInternal names inside a network.
DNSSECSigns records so tampering is detected.
DoH / DoTEncrypted DNS over HTTPS (443) or TLS (853).
DoQEncrypted DNS over QUIC.
6. Your resolvers All public ones are recursive, caching resolvers. Features can change, so verify with the tests in branch 7.
Router defaultForwarder with a small cache. Private IP, usually plain DNS, no filtering.
Cloudflare 1.1.1.1DoH, DoT, DNSSEC. No filtering (1.1.1.2 blocks malware).
Google 8.8.8.8DoH, DoT, DNSSEC. No filtering.
Quad9 9.9.9.9DoH, DoT, DNSSEC. Blocks known malicious domains.
AdGuard 94.140.14.14DoH, DoT, DoQ. Blocks ads, trackers, malware.
OpenDNS 208.67.222.222DoH, DNSCrypt. Phishing blocked; customizable with an account.
7. Test it yourself Turn each claim into a query that only works if the claim is true.
Which server am I using?resolvectl statusipconfig /all192.168.x.x means your router is a forwarder.
Who is really upstream?dig +short whoami.akamai.net @serverShows the IP that reached the authoritative side.
Recursive or authoritative?dig @server google.comFlag ra = recursive, aa = authoritative.
Caching?dig @server example.comRun twice. TTL counting down means cache.
Does it resolve on its own?dig +trace example.comRoot, TLD, authoritative walk from your machine.
DNSSEC validation?dig @server dnssec-failed.orgSERVFAIL means it validates. Look for flag ad.
Filtering?dig @9.9.9.9 domainCompare with @8.8.8.8. NXDOMAIN or 0.0.0.0 means blocked.
DoT support?kdig +tls @server example.comPort 853 must be open.
DoH support?curl -H 'accept: application/dns-json' 'https://server/dns-query?name=example.com'A valid answer over HTTPS.
Open ports?nmap -p 53,853,443 serverShows which DNS protocols are listening.
Plain-text leak?tcpdump port 53Traffic here means queries are unencrypted.
8. Reading dig output Every reply has a header, sections, and a footer. Each part is evidence.
Flag qrThis is a response, not a query.
Flag rdRecursion desired. Your query asked for it.
Flag raRecursion available. The server offers it, so it is a resolver.
Flag aaAuthoritative answer. The server owns this zone.
Flag adDNSSEC validated. Usually shown only if you ask with +dnssec or +adflag.
Flag cdChecking disabled. Skip DNSSEC validation.
Flag tcTruncated. Reply too big for UDP, retry over TCP.
status NOERRORQuery worked.
status NXDOMAINName does not exist (or was blocked).
status SERVFAILServer failed. Also what DNSSEC failure looks like.
status REFUSEDServer won’t answer you. Typical for authoritative-only servers.
opcode and idQUERY is normal. The id matches reply to request.
QUERY / ANSWER / AUTHORITY / ADDITIONALRecord counts in each section.
SectionsQUESTION (what you asked), ANSWER, AUTHORITY (who owns the zone), ADDITIONAL, OPT (EDNS).
Answer rowname TTL IN type data. TTL is seconds left to cache. IN is the Internet class.
EDNSExtension header: version, flags (do = DNSSEC OK), UDP size.
FooterQuery time, SERVER (IP, port, UDP or TCP), WHEN, MSG SIZE.

Tip: repeat tests from a second network to rule out ISP interference.
