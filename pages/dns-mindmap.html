DNS Mindmap

Eight branches to remember how DNS works, who plays which role, and how to test any server’s claims. Pick a branch in the side panel or search.

1. Roles in a lookup

Memory line: you ask the resolver, it asks root, then TLD, then authoritative.

Recursive resolver

Does the hunting for you and caches. ISP, 8.8.8.8, 1.1.1.1

Root server

Top of the tree. Points to the TLD server.

TLD server

Handles .com, .org, .in. Points to the domain’s server.

Authoritative server

Holds the real records. Gives the final answer.

2. Server configurations

Who owns the data, and who just passes it on.

Primary (master)

Original, editable zone data.

Secondary (slave)

Read-only synced copy for backup and load.

Caching-only

Remembers answers, hosts no zones.

Forwarder

Hands queries to another DNS server.

3. Query types

Recursive = “get me the answer”. Iterative = “tell me who to ask next”.

Recursive

Server must return a final answer or an error.

Iterative

Server returns a referral, client keeps asking.

Non-recursive

Answered from cache or the server’s own zone.

4. Record types

Names to addresses (A, AAAA), aliases (CNAME), mail (MX), and housekeeping.

A

Name to IPv4

AAAA

Name to IPv6

CNAME

Alias to another name

MX

Mail servers

NS

Authoritative name servers

TXT

Free text: SPF, DKIM, verification

PTR

IP to name (reverse lookup)

SOA

Zone admin info

SRV

Where a specific service lives

5. Other classifications

Who can use it, and how well is it protected.

Public

Internet-facing names and open resolvers.

Private

Internal names inside a network.

DNSSEC

Signs records so tampering is detected.

DoH / DoT

Encrypted DNS over HTTPS (443) or TLS (853).

DoQ

Encrypted DNS over QUIC.

6. Your resolvers

All public ones are recursive, caching resolvers. Features can change, so verify with the tests in branch 7.

Router default

Forwarder with a small cache. Private IP, usually plain DNS, no filtering.

Cloudflare 1.1.1.1

DoH, DoT, DNSSEC. No filtering (1.1.1.2 blocks malware).

Google 8.8.8.8

DoH, DoT, DNSSEC. No filtering.

Quad9 9.9.9.9

DoH, DoT, DNSSEC. Blocks known malicious domains.

AdGuard 94.140.14.14

DoH, DoT, DoQ. Blocks ads, trackers, malware.

OpenDNS 208.67.222.222

DoH, DNSCrypt. Phishing blocked; customizable with an account.

7. Test it yourself

Turn each claim into a query that only works if the claim is true.

Which server am I using?

resolvectl statusipconfig /all

192.168.x.x means your router is a forwarder.

Who is really upstream?

dig +short whoami.akamai.net @server

Shows the IP that reached the authoritative side.

Recursive or authoritative?

dig @server google.com

Flag ra = recursive, aa = authoritative.

Caching?

dig @server example.com

Run twice. TTL counting down means cache.

Does it resolve on its own?

dig +trace example.com

Root, TLD, authoritative walk from your machine.

DNSSEC validation?

dig @server dnssec-failed.org

SERVFAIL means it validates. Look for flag ad.

Filtering?

dig @9.9.9.9 domain

Compare with @8.8.8.8. NXDOMAIN or 0.0.0.0 means blocked.

DoT support?

kdig +tls @server example.com

Port 853 must be open.

DoH support?

curl -H 'accept: application/dns-json' 'https://server/dns-query?name=example.com'

A valid answer over HTTPS.

Open ports?

nmap -p 53,853,443 server

Shows which DNS protocols are listening.

Plain-text leak?

tcpdump port 53

Traffic here means queries are unencrypted.

8. Reading dig output

Every reply has a header, sections, and a footer. Each part is evidence.

Flag qr

This is a response, not a query.

Flag rd

Recursion desired. Your query asked for it.

Flag ra

Recursion available. The server offers it, so it is a resolver.

Flag aa

Authoritative answer. The server owns this zone.

Flag ad

DNSSEC validated. Usually shown only if you ask with +dnssec or +adflag.

Flag cd

Checking disabled. Skip DNSSEC validation.

Flag tc

Truncated. Reply too big for UDP, retry over TCP.

status NOERROR

Query worked.

status NXDOMAIN

Name does not exist (or was blocked).

status SERVFAIL

Server failed. Also what DNSSEC failure looks like.

status REFUSED

Server won’t answer you. Typical for authoritative-only servers.

opcode and id

QUERY is normal. The id matches reply to request.

QUERY / ANSWER / AUTHORITY / ADDITIONAL

Record counts in each section.

Sections

QUESTION (what you asked), ANSWER, AUTHORITY (who owns the zone), ADDITIONAL, OPT (EDNS).

Answer row

name TTL IN type data. TTL is seconds left to cache. IN is the Internet class.

EDNS

Extension header: version, flags (do = DNSSEC OK), UDP size.

Footer

Query time, SERVER (IP, port, UDP or TCP), WHEN, MSG SIZE.
